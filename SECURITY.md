# Security policy

Do not disclose vulnerabilities, credentials, personal data, or abuse paths in a public issue. Use GitHub's private vulnerability reporting or a private contact channel listed on the portfolio website.

Include the affected component, impact, safe reproduction steps, and mitigation ideas. Do not submit real customer data, trigger real emails or automations, create provider charges, or perform denial-of-service testing.

Only the latest deployed version is supported. Any exposed secret must be rotated even after it is removed from the repository.
